Enterprise Ground Transport (Dubai Client)

Context: A Dubai-based luxury ground transportation company ran their entire B2B partner booking flow through WhatsApp groups. Partners posted requests into group chats; staff manually checked vehicle/driver availability, calculated fares, and replied (~30 min turnaround during working hours, 2+ hours off-hours). WhatsApp's official Business API provides no support for group messages, ruling out vendor-sanctioned options.

Architecture & Components

  • Connection Layer (Go): Built on `whatsmeow`, managing WhatsApp session state, receiving/sending messages, read receipts, and typing indicators.
  • Agent Layer (Python / Google ADK): Multi-agent system:
    • Orchestrator: Supervises sub-agents and maintains shared conversational context.
    • Booking Agent: Extracts booking details from free-form messages; uses tools (flight data lookups, layered Google Maps queries for location resolution, backend availability/fare estimation). Asks targeted follow-up questions when requests are incomplete or contradictory.
    • Support Agent: Handles cancellations, modifications, rescheduling, and general inquiries.
  • Flight Data Service: Independent Python/ADK microservice on GCP Cloud Run acting as shared flight-lookup backend.

Outcome: Booking turnaround dropped from ~30 minutes to under a minute with zero recurring API costs.

Vertical Extension — Independent Musician

Extended the gateway for a musician handling 1,000+ daily messages across community groups:

  • Unknown Senders: Routed to dedicated support agent for service inquiries and class bookings.
  • Monitoring Service: Scans groups for relevant requests (call requests, performance bookings) and forwards only actionable messages into a private admin group.
  • Forwarding Service: Fan-out publishing allowing single post in admin group to auto-distribute to target destination contacts/groups.
