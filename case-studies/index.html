Engineering Case Studies Overview

Most of my project write-ups describe what got built. This page describes how I got there — the problem as it was first handed to me, what I found once I dug in, why the obvious first approach usually didn't hold, and the architecture that did. Written for anyone evaluating problem-solving process rather than just output.

Client Naming Note: Engagements where I was the direct, sole contracted engineer are named (Quantashift / MGS Technology / Hireups). Engagements that were TechieMaya's client relationships are described by industry and geography only.

Case Study 1: Data That Can't Leave the Building

Problem: A client needed AI-powered access to internal documents, but would not send data to any external service — ruling out standard cloud RAG architectures.

Analysis: A topology problem, not a modeling problem. The core question was whether reasoning could happen where data already lives, rather than moving data to cloud models.

Solution & Architecture: Inverted the RAG topology: deployed reasoning agents onto the client's local infrastructure using Agent-to-Agent (A2A) protocol. External tools query local agent endpoints while raw documents never cross the client's network boundary. Local index pairs dense vector search with keyword search across contracts, code, spreadsheets, and scanned PDFs.

Outcome: Established a repeatable pattern for "AI over data that can't move."

Case Study 2: Multi-Tenant AI Without Cross-Contamination

Problem: Businesses need personalized support agents, but dedicated per-client infrastructure doesn't scale, while naive shared infrastructure risks cross-tenant data leaks.

Analysis: The hard part was making RAG safely multi-tenant: strict isolation, per-client cost visibility, and avoiding single-vendor model lock-in.

Solution & Architecture: Agent-per-tenant model built on Google Agent Development Kit (ADK), with logical namespace vector isolation. A LiteLLM gateway manages cross-provider routing, rate limiting, and per-tenant cost attribution.

Outcome: One scalable backend serving multiple distinct clients securely with per-tenant billing transparency.

Case Study 3: 30 Minutes to Under a Minute — Automating a Manual Dispatch Desk

Client: A Dubai-based luxury ground transportation company (engagement held by TechieMaya).

Problem: B2B partner bookings were handled manually via WhatsApp group messages. Turnaround was ~30 minutes (2+ hours off-hours). WhatsApp Business API offers zero support for group messages.

Analysis: Two stacked problems: establishing a connection into group chats without official API support, and handling messy, incomplete, or contradictory booking requests through reasoning rather than keyword matching.

Solution & Architecture: Connection layer in Go built on `whatsmeow`. Multi-agent system on Google ADK (Orchestrator, Booking Agent with Google Maps and backend tools, Support Agent) plus an independent Flight Data service on Cloud Run.

Outcome: Turnaround dropped from ~30 minutes to under a minute with zero recurring API fees.

Case Study 4: Filtering Signal From a Thousand Messages a Day

Client: An independent musician (engagement held by TechieMaya).

Problem: Received 1,000+ daily messages across community groups, burying rare booking/session inquiries. Outbound announcements required manual reposting across dozens of chats.

Analysis: Inbound was a filtering/routing problem; outbound was a fan-out problem. Both could be solved by extending the existing WhatsApp connection layer.

Solution & Architecture: Added three services to the gateway: unknown sender support agent, group monitoring service forwarding actionable messages to a private admin group, and a fan-out forwarding service.

Outcome: Reduced daily read volume from 1,000+ to only actionable messages, solving inbound noise and outbound effort on existing infrastructure.

Case Study 5: Unblocking a Real-Time Avatar Product After Months Stuck

Client: MGS Technology Pvt Ltd, via Quantashift Consultancy Services (sole engineer).

Problem: Internal team was blocked for months getting LiveKit real-time video working for a photorealistic avatar interviewer product.

Analysis: The blocker was the real-time infrastructure layer. LiveKit self-hosting documentation was sparse, and client private servers on untrusted IP ranges broke standard SSL provisioning.

Solution & Architecture: Self-hosted LiveKit on GCP driving a photorealistic video avatar through Gemini Realtime (English & Arabic). Three deployments (GCP VM, Cloud Run persistent WebRTC, client private server with custom LiveKit build + ZeroSSL). Multi-LLM fallback chain (Gemini ➡️ Groq/Ultravox).

Outcome: Working real-time avatar interview system delivered end-to-end across three environments in a ~2-month engagement.

Case Study 6: One Voice Platform, Two Opposite Conversational Goals

Problem: Higher-ed consultancy needed natural, unhurried follow-up calls, while a real estate client needed persistent cold-calling. Both required sub-200ms audio round-trip latency.

Analysis: How a call is handled must be separated from what a call sounds like. Round-trip latency above 200ms breaks conversation realism.

Solution & Architecture: Self-hosted LiveKit on DigitalOcean (India) + UAE local LAN SIP modem deployment behind NAT. Dual regional workers + 3 Cloud Run bulk workers (scale-to-zero). Per-tenant configuration controlling tone, pacing, and goals on shared core infrastructure.

Outcome: One platform handling 1,000+ daily calls across education, real estate, and travel outreach without per-client codebase forks.

Case Study 7: Consistent Brand Content Without a Social Media Manager

Problem: Small/mid-size businesses lack social media managers, leading to uncertainty about what to post and slow execution when trying to recreate competitor concepts.

Analysis: The "what to post" gap needs live trend signal. The execution gap needs brand visual identity encoded into automated generation. Guided decision steps are required to prevent costly single-prompt video generation mismatches.

Solution & Architecture: Playwright brand website crawler + multimodal vision model compiling a persistent brand profile. Multi-agent hierarchy (Creative Director, Script Writer, Reference Selector, Dialogue & Voice, Video Generator with Google Veo + FFmpeg frame-anchoring, Reviewer). Subreddit sentiment scanner for trend signal. React/Next.js step-by-step decision UI with `contextvars` session cost accounting.

Outcome: Automated system providing trend-grounded post suggestions and finished on-brand creative without a design team.
